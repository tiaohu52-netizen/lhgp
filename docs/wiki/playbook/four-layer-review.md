# 四层代码审查

AI 写的代码「看起来对」的概率远高于「碰得住边界」的概率：它能写出完整的类型注解、
能让你 mypy 全绿、能给你一整页测试——然后在 M1/M11 这种地方错。所以审查不看
「读起来对不对」，只问四个可以被机械回答的问题。

**四层依次跑，一层一层过。发现的东西先记账，别边审边改**——边审边改会让后面的层
面对一个已经变形的对象，也会把「审查」和「修复」的边界糊掉。

| 层 | 一句话 | 产出 |
|---|--------|------|
| 1 类型 | 为什么是这个类型？ | 逃逸口清单（Each: 正当 / 偷懒 / 掩盖） |
| 2 死代码 | 这个导出有生产调用点吗？ | 每个公开名的三分类判定 |
| 3 边界 | 正则会不会误匹配？幂等吗？ | 探针实测输出，不是推理 |
| 4 跑一遍 | 真跑了？红绿是什么？ | gate 输出 + 反向验证记录 |

---

## 第 1 层 · 类型层

**要问的**：AI 为什么用这个类型？有没有 `Any` / `cast` 在偷偷放行？类型覆盖边界
（`None`）了吗？

```
uv run mypy                                  # 0 error 是起点，不是结论
grep -rn ": Any\|-> Any" src/ | wc -l        # 逃逸口总量
grep -rn "cast(\|type: ignore" src/          # 硬压
grep -rn "^from .* import \*" src/           # 星号导入：模块对 mypy 是黑箱
```

**判定用三种词，不要用「还行」**：

- **正当**：JSON payload、外部 SDK 边界、`dict[str, Any]` 装任意 schema 数据；
- **偷懒**：本该有 dataclass / TypedDict，用 `Any` 省事；
- **掩盖**：用 `Any` 或 `cast` 压住一条 mypy 报错——这一条最危险，因为它同时消灭了
  报错和「这里有问题」这个信息。

**`None` 边界**看两类点：`X | None` 返回值是否每处都有判定；`.get()` 链式调用
（返回 `Any`，静默吞掉类型与缺失）。

**本仓库的已知形状**：星号导入共 20 处，**全部在 `lhgp` 迁移 façade 层**
（`from longtask.X import *`）。这是设计上的迁移形态，但它有一个直接后果：
**façade 层对类型检查与死代码检测都是黑的**。所以第 1、2 层必须在真身侧做，
在 façade 上做的结论一律不算。

---

## 第 2 层 · 死代码层

**要问的**：这个导出有生产调用点吗？

**怎么数**：AST 收集模块的公开名，然后在 `src/` 里数**表达式引用**——必须排除

1. import 语句本身；
2. `__all__` 列表里的字符串；
3. **re-export façade 整文件**；
4. 定义它的那个文件自己（否则「内部自用」会被算成外部调用）。

**判定用三种词**：

| 判定 | 含义 | 处置 |
|---|---|---|
| 有生产调用点 | 真在用 | 无 |
| 有意测试可见 | 只为跨平台单测而导出（如 argv 构造函数） | 保留，但审查时写明理由 |
| **无引用** | 死导出 | 要么接上生产消费方，要么别导出 |

**最容易踩的坑（我第一次跑就踩了）**：把 re-export 当成调用点。`has_terminal_controls`
当时显示「1 个生产引用」，那个引用其实是 `lhgp/untrusted/__init__.py` 的转发行——
一个 re-export 撑起来的假调用点。**数之前先把 façade 文件整体排除。**

**为什么这层值得跑**：死的不只是一个函数。顺着「谁调用它」追下去，会撞上
**整套没有生产入口的机制**——本轮就是这么发现分区租约（`Partition` /
`check_partition_compatible` / `scope_paths` / `scope_stages`）只有测试在构造，
配套的 `lease/partition-conflict` 事件从未被发出、`PARTITION_CONFLICT` 错误码
从未被抛出、`partition_id` 在所有派工调用点都是默认值。

**死代码是「设计声明与运行时不符」的最强信号**：一个纯函数加几条单测就能全绿，
而它守护的东西在系统里根本不存在。

## 第 3 层 · 边界层

**要问的**：正则会不会误匹配？幂等吗？（M1 不误匹 M11）

**必须用探针跑，不许用推理**。把每条校验正则与每处前缀比较列出来，喂边界输入：

```
空串  "."  ".."  尾随换行 "ab\n"  尾随回车 "ab\r"  CRLF "ab\r\n"  尾随斜杠 大小写变体
一相对一绝对  前导/尾随空白
```

### 三条硬规则

1. **`$` 不等于串尾**。Python 里 `re.match(r"^ab$", "ab\n")` **是匹配的**——`$` 也匹配
   尾随换行之前的位置。统一用 `re.fullmatch`，或 `re.match` + `\Z`。
   *凡是 docstring 写了「fail-closed」「拒接」「防注入」的校验函数，必须有一条
   「尾随换行被拒」的用例*；没有这条用例的自称 fail-closed 不算数。

2. **前缀比较必须带分隔符**。`a.startswith(b)` 会把 `/p/ab` 误判成 `/p/a` 的子路径；
   正确写法是 `a == b or a.startswith(b + "/")`。本仓库的 `_path_prefix_overlap`
   写对了——但**它没做大小写归一化**（Windows 路径不敏感、POSIX 敏感），也**没有
   相对/绝对统一**（`src/x` 与 `C:/x/src` 判为不重叠）。凡是用路径做互斥判定的地方，
   这两件事都得显式回答。

3. **幂等要用随机语料 fuzz，不能只跑一个例子**。取几千条随机串（字母表里混入控制符、
   转义引导符、方向覆写符）验证 `f(f(x)) == f(x)`。

### 边界层的判定不是「有没有 bug」，而是「错了往哪边倒」

- **过松**（该拒的收了）= 真漏洞；
- **过严**（该收的拒了）= 可用性问题；
- **fail-closed 方向的过严是可接受的**，比如空 `scope_paths` 与任何路径都判重叠，
  会静默禁用并行——方向安全，但要在审查记录里写明「这是过拦，不是漏拦」。

## 第 4 层 · 跑一遍层

**要问的**：typecheck 和测试的红绿到底是什么？

```
uv run python scripts/quality_gate.py     # 7 门，本地与 CI 同一命令
```

「应该能过」不是结论。`mypy` 全绿 + 测试全绿也**只证明现有断言没被违反**，
不证明新代码的断言抓得住东西。

### 反向验证（这一层真正的核心）

**每条新测试都要做一次变异**：把被测的那个行为改坏，那条测试必须变红，
**而且变红的必须正是你预期的那个测试名**。

可用变异手法：把返回值写死、把旗子恒置 False、摘掉一次转换、把 `\Z` 换回 `$`、
让判定的另一侧成立。

**判据必须包含「失败测试名 == 预期名」**。本轮差点记错一次：变异只改到了
`collect()` 的 **`finished_event` 分支**，而测试走的是常规分支，于是测试照绿——
如果只看「returncode != 0」，就会把**没抓到东西的装饰性测试**写成「已验证」。
节点 id 打错导致的收集失败也是非零退出，同样会伪装成「变红」。

```
# 变异验证的最小形态：改坏 → 只跑那条测试 → 断言「变红」且失败名匹配 → 还原
# 判据: returncode != 0  且  FAILED 行里出现预期测试名  且 不是收集错误
```

## 本轮实测（2026-09-10，作为四层的样例记录）

| 层 | 发现 |
|---|---|
| 1 类型 | `Any` 496 处、`cast(` 3、`type: ignore` 4；星号导入 20 处全在 façade → 审查只能在真身侧做 |
| 2 死代码 | 3 个新导出无生产调用点（1 个接上了生产消费方，2 个判定为「有意测试可见」）；追出整套分区租约机制只有测试在调用 |
| 3 边界 | 4 个标识符校验器**全部**被尾随换行穿过（含 1 个自写的、docstring 明写 fail-closed）；20000 条 fuzz 验幂等通过；`_path_prefix_overlap` 的 M1/M11 写法正确但缺大小写与相对/绝对归一化 |
| 4 跑一遍 | 7 门全绿；3 条新测试做反向验证，其中 1 条第一次变异**打偏分支**、重做才确认真有效 |

## 反模式

- **只跑 mypy 就宣布类型没问题**：0 error 与「类型表达了约束」是两件事。
- **在 façade 上下结论**：星号导入的模块对类型与死代码检测都是黑的。
- **把 re-export 算成调用点**：会得出「有人在用」的假结论。
- **用推理代替探针**：M1/M11 和 `$` 这一类错，推理时脑子里那个例子恰好都是对的。
- **只跑一个例子的幂等检查**：单例通过说明不了任何事。
- **用「测试没过」当反向验证**：节点 id 打错、收集失败也是非零退出。
- **边审边改**：后面的层会面对一个已经变形的对象，且审计记录失去「改前」状态。

## 验证清单

- [ ] 逃逸口（`Any`/`cast`/`type: ignore`/星号导入）逐个判为正当 / 偷懒 / 掩盖
- [ ] 星号导入的模块没有被当作审查对象（结论取自真身侧）
- [ ] 每个公开导出三分类，排除 import / `__all__` / re-export stub / 定义处
- [ ] 每条校验正则与每处前缀比较都过了边界输入探针
- [ ] 自称 fail-closed 的函数有「尾随换行被拒」用例
- [ ] 幂等检查用随机语料，不是单例
- [ ] `quality_gate.py` 全绿
- [ ] 每条新测试做过变异反向验证，且失败测试名与预期一致

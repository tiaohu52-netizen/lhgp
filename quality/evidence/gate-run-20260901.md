## 本次变更内容

1. 补完调度分发逐候选拒接重试（DESIGN §8.3/§9/§10 时序）：
   `longtaskd` tick 对 `match_candidates` 有序候选逐个执行 prepare 探针，
   拒接记录 `dispatch/refused` 事件（入库 + log.jsonl 投影）并换下一个候选，
   全部耗尽转 blocked(no-executor)；prepare 兑现才占租约、记 attempt/started。
   spawn 仍由 control/spawn 桥接层负责，本变更只做调度簿记。
2. 新增 `longtask.adapters.factory.build_adapter`：kind → 适配器默认构造，
   未知 kind 返回 None（分发侧按拒接处理，fail-closed 不猜）。
3. `AttemptInput.task_prompt` 落地传递：spawn 将任务文本（冻结区 objective，
   用户审定数据）作为单个 argv 尾元素传给 headless CLI；空白拒接。
4. `run_daemon_tick` 新增可选 `adapter_factory` 注入（默认 build_adapter）。
5. 测试：新增调度级拒接换下一候选一致性场景、factory 单测、
   task_prompt 单尾元素（含 shell 元字符）与空白拒接两场景；
   调度测试合同补声明 workspace_root（prepare 探针要求可绑定工作区）。

# LHGP：产品一页纸

> 本文是非规范性摘要。语义以 [LHGP-SPEC.md](../LHGP-SPEC.md) 为准，
> 定位决策见 [ADR-004](../decisions/0004-contract-runtime-and-release-scope.md)。

## 一句话定位

**限期合同中枢（Deadline Contract Hub）——独立于会话和模型的多 Agent 任务合同运行时，支持远期目标的持续推进与证据化验收。**

协议仍名为 Long-Horizon Goal Protocol（LHGP，远期目标协议）。
“远期目标”描述主要场景，“任务合同运行时”描述系统类别，
“限期合同中枢”是产品名称；不另起包名或工具命名空间。

## 用户交给它什么

结果、验收标准、Deadline、预算、权限和允许参与的执行者。
用户可以直接建立合同，也可以请 Agent 协助起草；同一运行时能持有多份合同。
合同保存在本机，不依赖最初会话继续存在。

## 内核和模型各做什么

- 确定性内核：合同状态、预算约束、调度决策、租约与执行监督、事件和验收裁决。
- 可替换执行者：Agent CLI 或普通程序，承办一次 attempt 并交回产物与证据。
- 可选模型能力：起草、执行、语义验收；未来规划器通过受校验入口提出计划建议。

内核不需要 LLM 常驻。Goal 的持久化阶段计划和关联合同已有实现，
当前推进使用外部提交的计划；自主语义拆解／重规划与全局最优资源调度尚未实现。

## 首发范围

单机、单用户，多合同管理，授权执行者接力，Deadline 风险，
结构化检查与独立验收，CLI/MCP 入口及插件 companion 包。
必须先修复已发现的控制权和预算错误，再验证最终制品；不以功能清单和测试数量代替发布验收。

首发级别为 Developer Preview。以 [RELEASE-PLAN.md](../RELEASE-PLAN.md) 的 R1–R6 为截止线，
满足后即可发布，不等待可选规划器、复杂 UI 或命名空间物理迁移。
目前仍有已复现阻断项，见[发布检查](../evidence/release-readiness-2026-09-05.md)。

## 不承诺什么

- 精确到某一时刻必然完成，或机器关机时继续在本地执行。
- 跨主机／跨网络中继、多租户服务。
- 任意共享工作区的安全并行写入、任意 CLI 的无条件兼容。
- 把模型自报成功当作验收通过，或把上下文摘要当作唯一权威存储。
- 在没有结构化计划输入时自主理解并持续改写任意远期目标。

## 发布后的验证方向

1. Deadline：记录预测与实际工时、等待和验收成本，改善风险校准和可解释性。
2. 多合同调度：从独立工作区开始，建立可测试的公平性、容量和冲突规则。
3. 可选规划器：提出结构化建议；不直接越过用户授权、合同预算和验收规则。
4. 上手体验：通过真实用户反馈改进模板和预检，而非增加必需的总控模型。

这些是后续任务，不是已验证能力，也不是首发全部完成的前提。
